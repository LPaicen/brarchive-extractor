`brarchive-extractor` is a TypeScript command-line tool for Minecraft Bedrock resources. It extracts individual or batched `.brarchive` files and can restore MCB binary documents to JSON using schemas generated by [bedrock-apis/bds-docs](https://github.com/bedrock-apis/bds-docs).

The installed command is the short alias `brax`.

The tool validates archive bounds, path traversal, output conflicts, and trailing MCB data. Failed MCB restorations preserve the original binary by default and processing continues.

## Installation

Node.js 20 or newer is required:

```powershell
npm install
npm run build
npm link
```

## Basic Usage

Extract one archive:

```powershell
brax .\entities.brarchive
```

Restore MCB files with a BDS schema export:

```powershell
brax .\entities.brarchive --schema .\bds-schema
```

Process a directory recursively:

```powershell
brax .\input --schema .\bds-schema
```

Results normally go to `<input-name>_unpacked` beside the input. Use `--output` to select another output root, or `--in-place` to write directly into the source layout:

```powershell
brax .\input --in-place --schema .\bds-schema
```

`--in-place` directly modifies ordinary MCB/JSON source files and writes archive entries into their logical directories. A single `foo.brarchive` writes to the sibling `foo/` directory while preserving the archive. It cannot be combined with `--output`, `--split-archives`, or `--force`; back up the input before using it.

For a non-empty output directory, use `--overwrite` to preserve unrelated content and replace matching files. Use `-f` or `--force` to clear the entire output directory before processing. Clearing is irreversible, and `--force` cannot be combined with `--overwrite`.

Ordinary files in directory inputs are copied unchanged unless `--format-all-json` applies. `--mcb-only` ignores all non-MCB content. `--no-empty-dirs` omits archive output directories that contain no extracted files; reports do not make an otherwise empty directory eligible. Use `--split-archives` to keep `foo.brarchive/` output separate from a sibling `foo/` tree.

## Schema

`--schema` may point to a standard bds-docs export or any directory containing JSON Schemas. The tool prefers `metadata/json_schemas/` when present; otherwise it scans the specified directory recursively. The only schema requirement is that at least one valid JSON file has `$id`.

## Conflicts

Normally, a same-named `foo.brarchive` and `foo/` under `__brarchive` are complementary: the archive stores direct files for the current level, while the directory stores child brarchives. They therefore do not conflict. If malformed input causes multiple contents to occupy one merged target, the tool pauses and displays the sources and total conflict count.

Enter `o`, `k`, or `c` to overwrite, keep the existing file, or coexist as `name (1).ext`. Uppercase `O`, `K`, and `C` apply that decision to every remaining conflict. An unresolved conflict in a non-interactive terminal is a fatal error.

## Command Options

```text
-d, --directory          Treat the input as a directory
-r, --recursive          Scan directories recursively (default)
    --no-recursive       Scan only the first input-directory level
-s, --schema <path>      bds-docs export or recursive schema directory
-o, --output <path>      Select the output root
-w, --overwrite          Overwrite matching existing output files
-f, --force              Clear the entire output directory first
-p, --report             Write .brarchive-report.json for each archive
    --verbose            Show status and progress (default)
    --no-verbose         Disable status and progress
-l, --list               List failure details only
-L, --list-all           List archive, failure, and conflict details
-j, --json-format <mode> Use pretty or compact restored MCB JSON
-J, --format-all-json    Format ordinary .json files; preserve comments
    --indent-size <0-10> Pretty JSON indentation width (default: 2)
    --indent-char <value> Indent with space or tab (default: space)
-F, --fail-fast          Stop after the first parsing failure
-D, --discard-failed     Do not write failed files; ignored with --fail-fast
    --mcb-only           Extract and restore MCB only
    --no-empty-dirs      Do not create directories without extracted files
    --split-archives     Keep same-named archives and directories separate
-i, --in-place           Write directly into the source layout
-h, --help               Show help
-v, --version            Show version
```
